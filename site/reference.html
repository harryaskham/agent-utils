Reference

Installing, configuring and testing Agent Utils. The long-form guides for each extension live in the repository's docs/.

Install

The Pi package installs every extension, prompt template and theme at a tagged release:

pi install git:github.com/harryaskham/agent-utils@v1

The standalone tools are flake packages:

nix build .#ag              # fleet speech, images, audio, questions and healthnix build .#pi-session      # fork sessions between machinesnix build .#skill-search    # skill and MCP discovery (also skill-server)nix build .#durable-extensions  # speech and media modules for pi-daemon sessions

Working with a session host

Every extension must work on its own. When the Paratenic session host is present, portable features are also offered to its remote clients through the Agent Host Protocol, under a few rules:

  • Agent Utils owns the behaviour, user interface, policy and device adapters; the host's Pi plugin is only a thin, generic transport.
  • Agent Utils discovers a versioned structural bridge rather than importing the host's code.
  • Local and remote input enter the same state machine, with exactly-once correlated commands; there is never a second copy of the state.
  • Images shared into context become durable host attachments; local previews stay local.
  • A capability is advertised only after it works end to end and passes conformance tests.

Testing

npm test                 # 179 test files on Node's built-in runner, no frameworksnpm run check            # lint workflows and validate this sitecargo test               # the Rust cratesnpm run test:choice-ui   # real-terminal checks of the choice interface

Extensions keep their Pi, process and terminal surfaces thin and put logic in pure modules that tests import directly. Slow or environment-dependent checks, such as a real kitty preview reload or a model-restore process, are opt-in behind environment variables.

This site is built from site/ by scripts/site/build.py and checked by scripts/check-site.py.
